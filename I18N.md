# Internationalization (planned)

## Current policy

- **Default language:** **English (en)** for all user-visible strings in the app and for all **public** repository documentation.
- **Code comments:** English.

## Roadmap

Internationalization (**i18n**) will be added in a dedicated milestone after the core desktop loop is stable. Target is **runtime locale switching** (or OS-locale detection with manual override — TBD).

### Candidate locales (non-exhaustive)

The final list will be confirmed before implementation. Likely high-priority candidates include:

| Locale | Language (endonym) | Notes |
|--------|--------------------|--------|
| `es` | Spanish | |
| `ru` | Russian | |
| `zh` | Chinese (script/region split TBD: e.g. `zh-Hans` vs `zh-Hant`) | |

Additional locales may follow (e.g. Portuguese, French, Japanese) based on demand.

## Implementation (TBD)

- Library choice (e.g. **react-i18next**, **Lingui**, or **FormatJS**) will be decided when i18n work starts; it must play well with **Tauri + Vite** and allow **lazy-loaded** message catalogs.
- **String extraction** from components and a **translation workflow** (keys, reviews, fallbacks) will be documented in this file or in `docs/` when i18n lands in the repo.

Until then, **do not** mix non-English copy in tracked UI or public docs; keep locale-specific text in future message files only.
